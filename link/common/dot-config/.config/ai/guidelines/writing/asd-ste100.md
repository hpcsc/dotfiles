# ASD-STE100 Simplified Technical English

Write documents in Simplified Technical English. The goal is one meaning per sentence, readable by someone
who is tired, in a hurry, or reading in a second language.

This governs the document you write. It does not govern your reply in chat.

## Words

**One word, one meaning, one part of speech.** Pick a term and keep it for the whole document. Do not
switch between synonyms for variety.

- Bad: `the hold suppresses comms` … `the snooze stops messages` … `the block pauses outreach`
- Good: `the hold stops communications` (every time)

**Use the plain word.** Common replacements:

| obtain, acquire | get |
| ensure | make sure |
| verify | check |
| provide | give, send |
| request (verb) | ask for |
| display, indicate | show |
| commence, initiate | start |
| terminate | stop, end |
| occur | happen |
| remain | stay |
| resume | start again |
| suppress | stop |
| perform | do |
| assist | help |
| attempt | try |
| require | need |
| possess | have |
| sufficient | enough |
| approximately | about |
| additional | more, other |
| multiple | many, more than one |
| currently | now |
| prior to | before |
| subsequent to | after |
| in order to | to |
| due to the fact that | because |
| via | with, through |
| per | for each |
| e.g. | for example |
| i.e. | that is |
| however | but |
| thus, hence | therefore |

**Do not use etc.** List the items, or write "and other" plus a noun.

**Modal verbs:** use `must` for an obligation and `can` for a possibility. Do not use `should`, `would`,
`could`, `may`, or `might`.

**Do not use contractions.** Write `do not`, not `don't`.

## Sentences

**Keep sentences short.** 20 words is the limit for an instruction. 25 words is the limit for a
description.

**One instruction per sentence.** Split a compound instruction into two sentences or a vertical list.

**Use the active voice.**

- Bad: `the hold is applied when the case is submitted`
- Good: `the reactor applies the hold when the platform submits the case`

**Use simple tenses only.** Simple present, simple past, simple future. No perfect tenses and no continuous
tenses.

- Bad: `the module has raised the ticket and is waiting for a reply`
- Good: `the module raised the ticket. It now waits for a reply`

**Do not use `-ing` verb forms.** Rewrite as a finite verb or a noun.

- Bad: `after opening the case, the reactor sends the request`
- Good: `the reactor opens the case. Then it sends the request`
- Bad: `the following steps`
- Good: `these steps`

**Keep the articles.** Write `the case`, not `case`.

**Use a maximum of three nouns together.** Break longer clusters with a preposition.

- Bad: `customer case expiry configuration default value`
- Good: `the default value in the configuration for case expiry`

## Paragraphs

- Give a topic sentence first, then support it.
- One topic per paragraph.
- Six sentences is the limit.
- Put complex material in a vertical list or a table, not in prose.

## Do not use

- Metaphors and idioms: `the timer fires`, `the clock is ticking`, `this collapses into`, `findings that
  bite`, `split-brain`, `park the deadline`
- Slang and jargon that is not a technical name
- Rhetorical questions
- Humour and understatement

Write what happens:

- Bad: `the deadline fires and the case is welded to one outcome`
- Good: `the schedule sends the message at the deadline. The case then always resolves with the same
  outcome`

## What does not change

Simplified Technical English applies to your own prose. Leave these as they are:

- Quotations from a source document, and text that a customer or a client receives
- Technical names: identifiers, event names, file paths, field names, code
- Proper nouns and product names

## Review

Check the finished document for:

- Words from the replacement table
- Sentences longer than the limit
- `-ing` verb forms and perfect tenses
- Passive voice that can become active
- Two words used for one meaning
- Metaphors
