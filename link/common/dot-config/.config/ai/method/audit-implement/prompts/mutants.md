CHECKED BY MUTATION. Before you started, `clerk mutants` changed each line that this diff changes, one change at a time, and ran the tests of the package. Each row under MUTANTS is a change that no test caught: LIVED means the tests pass with the change, and NOT COVERED means no test runs the line. A row with a sentence in place of the code is a mutant that an agent proposed for the domain. A row under CALLER GAPS is changed code that the tests of its own package run, but that no test of a changed caller runs.

Judge each row. A row that shows a behaviour no test pins is a finding: set `mutant_id` to its id, and say in `claim` which behaviour is unpinned. A caller gap that matters is a finding about the caller's tests. A row that changes only a log line, an error text, an equivalent value, or nothing that a caller can see goes in `note`, with the reason. Do not raise a row again that you put in `note`.
