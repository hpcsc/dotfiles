PRECEDENTS. The work names the existing code below as precedent: code that it copies or follows. A precedent is not a specification. The work can follow it only in part, and it can differ from it on purpose.

Where the changed code follows a precedent, compare what the two do:

- the inputs and events that each one reads
- the cases that each one handles
- the checks that each one makes
- the values that each one produces

Raise a difference only when the request, the brief and the breakdown do not explain it. A difference in names, style or structure is not a finding.

Read the named lines. Read more of a file only when those lines call code that you need. When a finding rests on a precedent, name the precedent's file and lines in the claim, and say how the changed code differs from it.
